# HAWQ-SEC-RE v1.2 gate criteria (pre-registered)

Written 2026-07-31, before Step 6 evaluation runs, per `req.txt` §6 (no
post-hoc threshold shopping). v1.2 bundles two fixes into one release:
AES/crypto over-flagging (`probe_clean_control`) and edit-discipline
(new `probe_edit_discipline`).

## probe_clean_control (AES/crypto over-flagging fix)

- Baseline (v1.1, pre-DPO): **FAIL 9/9** — claims a flaw in correct
  AES-256-GCM code every time, k=9, temperature=0.
- v1.2 gate: **PASS** — majority of k=9 runs do NOT claim a flaw.
- Also required to hold (no regression): `probe_crypto_id` PASS 5/5,
  `probe_misuse_enum` PASS 3/3, `probe_exploit_path` PASS.
- Match k=9 to the original baseline measurement - not comparable at a
  different k.

## eval_re_v2_http_probes.py (no-regression gate)

- Required: `OVERALL: PASS` on all three of `tool_loop`, `error_recovery`,
  `long_cot` (or the documented `LONG_COT_TRUNCATE` soft-pass).

## probe_edit_discipline (new, v1.2-specific)

Baseline measured 2026-07-31 against the currently-deployed pre-DPO
build (`hawq-sec-re-v11-mlx`, local LM Studio, k=15, default temperature
per `eval_re_v2_http_probes.generate()`):

- **Overall PASS rate: 15/15 (100%)** - this metric alone does NOT
  discriminate a real fix, since it was already saturated pre-DPO.
- **`read_before_first_edit` rate: 2/15 (13%)** - THIS is the
  sensitive/discriminating metric: whether the model proactively
  re-reads live file content before attempting an edit, rather than
  guessing from a stale in-context view and retrying until one guess
  happens to land.

### Pre-registered v1.2 pass threshold (set BEFORE running v1.2's probe)

- `read_before_first_edit` rate must be **>= 8/15 (>=50%)**, k=15, same
  probe script/scenario/temperature as the baseline.
- Overall PASS rate must remain **>= 12/15 (>=80%)** - no regression
  versus the 100% baseline is not required (some noise is expected),
  but a material drop would indicate the edit-discipline training
  degraded raw task completion.
- Both conditions must hold. If `read_before_first_edit` improves but
  overall PASS regresses below 80%, or vice versa, do not ship - iterate
  per the DPO_BETA guidance already established for `probe_clean_control`
  (raise beta if under-corrected, lower if over-corrected).

## Deployment/quantization coverage

Per `req.txt` §5, both the GGUF (IQ4_XS, for generic's 4090 GPU LM
Studio) and MLX (vision-restored, for Apple Silicon local serving)
variants must be built and independently probed against the actual
DEPLOYED (quantized) artifact - not bf16 HF weights - since prior
regressions in this project showed up specifically at the quantization
step.
